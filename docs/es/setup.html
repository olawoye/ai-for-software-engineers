1.2 Configuración en Windows (usando WSL2)

Si utilizas Windows 10 o Windows 11, este curso recomienda encarecidamente desarrollar dentro de Windows Subsystem for Linux 2 (WSL2). Aunque Python puede instalarse directamente en Windows, WSL2 ofrece un entorno Linux totalmente compatible con las herramientas modernas de IA y desarrollo de software.

¿Por qué WSL2?

  • El curso incluye scripts de Bash para la configuración y el lanzamiento de aplicaciones.

  • La mayoría de los frameworks de IA se desarrollan y prueban principalmente en Linux.

  • La instalación de paquetes suele ser más fiable.

  • Las rutas de archivos y los entornos virtuales se comportan de forma consistente con los ejemplos demostrados durante el curso.

  • Obtienes experiencia usando el mismo sistema operativo utilizado por muchos servidores en la nube y entornos de desarrollo.

Paso 1 — Instalar Windows Subsystem for Linux

Abre Windows PowerShell como administrador.

Ejecuta el siguiente comando.

wsl --install

Este comando instala Windows Subsystem for Linux junto con la distribución predeterminada de Ubuntu.

Cuando termine la instalación, reinicia tu equipo si se te indica.

Después de reiniciar, Ubuntu se iniciará automáticamente y te pedirá que crees un nombre de usuario y una contraseña de Linux. Estas credenciales solo se utilizan dentro de tu entorno Linux.

Nota

Tu nombre de usuario y contraseña de Linux son distintos de tus credenciales de inicio de sesión en Windows.

Paso 2 — Verificar la versión de WSL

Abre PowerShell otra vez y ejecuta:

wsl --list --verbose

Deberías ver una salida similar a:

NAME      STATE     VERSION

Ubuntu    Running   2

El valor importante es la columna VERSION, que debería ser 2.

Si tu instalación informa la versión 1, actualízala con:

wsl --set-version Ubuntu 2

Paso 3 — Abrir Ubuntu

Puedes abrir Ubuntu de varias formas.

Method            Description
----------------  -------------------------------------------------
Start Menu        Open Ubuntu directly from the Windows Start Menu.
PowerShell        Run wsl.
Command Prompt    Run wsl.
Windows Terminal  Select the Ubuntu profile.

A partir de este punto, todos los comandos que se muestran en este curso deben ejecutarse dentro del terminal de Ubuntu, salvo que se indique lo contrario.

Paso 4 — Actualizar Ubuntu

sudo apt update && sudo apt upgrade -y

Esto puede tardar varios minutos según tu conexión a internet.

Deberías tener Python 3.11 o una versión posterior.

Si Python falta o tu versión es anterior, instálala con:

sudo apt install python3 python3-pip -y

sudo apt install build-essential curl git -y

Esto instala:

  • G++

  • Make

Paso 7 — Verificar Git

git --version

Deberías ver una versión de Git 2.x o superior.

Después de completar esta sección, puedes tratar tu terminal de Ubuntu casi exactamente como un terminal de Linux o macOS. A partir de este punto, casi todos los comandos que se muestran a lo largo del curso son idénticos, tanto si usas macOS como si usas Windows con WSL2.

¿Qué hace el script de configuración?

Step                    Description
---------------------  ---------------------------------------------------
Python Verification     Checks that Python 3.11 or newer is available.

¿Por qué usar un entorno virtual?

Un entorno virtual es una instalación aislada de Python que pertenece solo a este proyecto. En lugar de instalar paquetes globalmente en tu computadora, cada proyecto mantiene su propio conjunto independiente de librerías.

Esto evita conflictos de versiones entre diferentes proyectos y garantiza que todos los que sigan este curso trabajen con exactamente las mismas versiones de dependencias que se demuestran a lo largo de las lecciones.

Dependiendo de tu conexión a internet, el proceso de instalación puede tardar varios minutos porque numerosas librerías de IA, incluidas Streamlit, LangChain, OpenAI, ChromaDB y otras dependencias, deben descargarse e instalarse.

Por favor, ten paciencia

La primera instalación siempre es la más larga. Después de que las dependencias se instalen correctamente, las lecciones futuras se lanzan casi de inmediato porque los paquetes ya están disponibles en tu máquina.

Verifica la instalación

Deberías ver una entrada similar a:

Esto confirma que tu entorno virtual aislado se ha creado correctamente.

2.5 Configuración de variables de entorno

Muchas lecciones se comunican con modelos de lenguaje grande usando APIs en la nube. Estos servicios requieren autenticación mediante claves API.

En lugar de colocar información sensible directamente en el código fuente, las aplicaciones modernas almacenan credenciales como variables de entorno. Esto mejora la seguridad y facilita cambiar entre distintos proveedores.

Variables de entorno temporales

Si solo quieres experimentar, puedes definir claves API para la sesión actual del terminal.

export OPENROUTER_API_KEY="your-api-key"

export OPENAI_API_KEY="your-openai-key"

export ANTHROPIC_API_KEY="your-anthropic-key"

export COHERE_API_KEY="your-cohere-key"

export OLLAMA_URL="http://localhost:11434/completions"

Estos valores permanecen disponibles hasta que se cierre la ventana del terminal.

Puedes verificar una variable de entorno con:

echo $OPENROUTER_API_KEY

Configuración persistente usando un archivo .env

Para el desarrollo diario, almacenar la configuración en un archivo .env es considerablemente más conveniente.

Crea un archivo llamado .env en la raíz del repositorio.

OPENROUTER_API_KEY=your-api-key

OPENAI_API_KEY=your-openai-key

ANTHROPIC_API_KEY=your-anthropic-key

COHERE_API_KEY=your-cohere-key

OLLAMA_URL=http://localhost:11434/completions

Dentro de Visual Studio Code, busca la configuración llamada Python: Env File y señala el archivo .env del proyecto. Los nuevos terminales cargarán estos valores automáticamente.

Recordatorio de seguridad

Tus claves API son credenciales privadas. Nunca las publiques en línea, nunca las incluyas en capturas de pantalla y nunca confirmes tu archivo .env en GitHub. El repositorio ya incluye un archivo .gitignore que evita confirmaciones accidentales.

Cómo usa el curso estas variables

Las utilidades compartidas de configuración leen estas variables de entorno cada vez que inicia una lección.

Variable              Purpose
--------------------  ---------------------------------------------
OPENROUTER_API_KEY     Recommended provider for most lessons.
OPENAI_API_KEY         OpenAI models.
ANTHROPIC_API_KEY      Claude models.
COHERE_API_KEY         Embedding generation.
OLLAMA_URL             Local LLM endpoint.

Las lecciones individuales indicarán qué proveedor requieren. En la mayoría de los casos, OpenRouter es el proveedor recomendado por defecto porque ofrece acceso a múltiples modelos a través de una sola API.

3.1 Configuración de OpenRouter (recomendada)

OpenRouter actúa como una pasarela unificada para muchos de los modelos de lenguaje más populares del momento.

En lugar de crear cuentas con varios proveedores de IA, OpenRouter permite que tus aplicaciones accedan a numerosos modelos usando una sola API.

¿Por qué OpenRouter?

  • Proceso de registro sencillo.

  • No se requiere tarjeta de crédito para el plan gratuito.

  • Acceso a múltiples proveedores de modelos.

  • Excelente para aprender y experimentar.

  • Una interfaz API única sin importar qué modelo elijas.

Paso 1 — Crear una cuenta

Visita el sitio web de OpenRouter y crea una cuenta gratuita.

Puedes registrarte usando tu dirección de correo electrónico, tu cuenta de GitHub o tu cuenta de Google.

Paso 2 — Generar una clave API

Después de iniciar sesión, ve a la página de API Keys y genera una nueva clave.

Tu clave tendrá un aspecto similar a:

sk-or-v1-xxxxxxxxxxxxxxxxxxxxxxxx

Importante

Trata tu clave API como si fuera una contraseña. Cualquier persona que tenga tu clave puede hacer peticiones en tu nombre.

Paso 3 — Añadir créditos (recomendado)

Esto es opcional, pero añadir entre $5 y $10 puede desbloquear límites bastante generosos.

Paso 4 — Configurar tu entorno

Si estás usando un archivo .env, simplemente añade:

OPENROUTER_API_KEY=sk-or-v1-your-api-key

Alternativamente, configúralo temporalmente en tu terminal.

export OPENROUTER_API_KEY="sk-or-v1-your-api-key"

Verifica que la variable se haya configurado correctamente.

echo $OPENROUTER_API_KEY

Cómo usa el curso OpenRouter

La configuración del curso lee tu clave API de OpenRouter cada vez que una aplicación se inicia.

Para la mayoría de las lecciones, no se requiere configuración adicional. Una vez añadida tu clave API, los proyectos completos demostrados a lo largo del curso se comunicarán con OpenRouter automáticamente.

Detrás del escenario

Las utilidades compartidas de configuración dentro del repositorio cargan tus variables de entorno y configuran el proveedor correcto automáticamente. Esto mantiene el código de las lecciones limpio y permite cambiar de proveedor sin modificar la lógica de la aplicación.

3.2 Configuración de la API de Cohere (embeddings)

La mayoría de las lecciones usan modelos de lenguaje generativos, pero varias lecciones más adelante introducen embeddings vectoriales para búsqueda semántica y Recuperación Aumentada por Generación (RAG).

Esas lecciones usan la API de embeddings de Cohere.

¿Por qué Cohere?

  • Modelos de embeddings de alta calidad.

  • API REST sencilla.

  • Plan gratuito generoso.

  • Documentación excelente.

Paso 1 — Crear una cuenta

Crea una cuenta gratuita en Cohere.

Paso 2 — Generar una clave API

Copia tu clave API desde el panel de control.

Paso 3 — Añadir la variable de entorno

COHERE_API_KEY=your-cohere-api-key

o temporalmente:

export COHERE_API_KEY="your-cohere-api-key"

Verifica la configuración.

echo $COHERE_API_KEY

¿Cuándo necesitarás esto?

No necesitas una clave API de Cohere de inmediato. Solo unas pocas lecciones que implican embeddings y búsqueda semántica la requieren, y cada lección indicará claramente cuándo es necesaria.

3.3 Proveedores opcionales

El curso es agnóstico respecto al proveedor. Si ya tienes suscripciones con otros proveedores de IA, puedes usarlos en su lugar.

OpenAI

Si ya tienes una cuenta de desarrollador de OpenAI, añade:

OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxx

Los modelos de OpenAI pueden usarse en varias lecciones avanzadas, aunque OpenRouter sigue siendo el valor recomendado por defecto.

Anthropic (Claude)

Si ya usas Claude, configura:

ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxx

Muchos alumnos disfrutan comparando las respuestas de Claude con las producidas por otros proveedores.

Ollama local

Si prefieres ejecutar modelos de lenguaje completamente en tu propia máquina, Ollama es una alternativa excelente.

Instala Ollama, inicia el servidor local y luego configura:

OLLAMA_URL=http://localhost:11434/completions

Tus aplicaciones se comunicarán directamente con tu máquina local en lugar de un servicio en la nube.

Modelos locales

Ejecutar modelos localmente elimina los costes de API y permite experimentar sin conexión, aunque los modelos más grandes requieren recursos significativos de CPU y memoria.

4.2 Ejecutar el panel de Streamlit (recomendado)

La forma principal de explorar este curso es a través del panel de Streamlit.

Streamlit permite que las aplicaciones Python rendericen interfaces de usuario interactivas directamente en tu navegador sin requerir desarrollo en HTML, CSS o JavaScript.

Lanzar el panel

Alternativamente, usa el script de conveniencia proporcionado.

Después de unos momentos, deberías ver una salida similar a:

You can now view your Streamlit app in your browser.

Local URL: http://localhost:8501

Debería aparecer el panel del curso, con acceso a cada módulo y lección.

Ejecutar una lección

Simplemente:

  3. Proporciona cualquier entrada requerida.

  4. Haz clic en el botón adecuado.

Muchas lecciones también guardan resultados intermedios para usarlos en ejercicios posteriores.
