Pre Code Lessons — Technical Environment Setup

Starting from Module 2, you are going to see practical code demonstration lessons. Before we begin writing AI-powered applications, we need to prepare a modern Python development environment that will be used throughout the remainder of this course.

The good news is that this setup is only performed once. Once your environment is configured correctly, every lesson in the course follows exactly the same workflow.

This course has been designed so that you can immediately run and study complete, working implementations. Every lesson demonstrated throughout the videos already exists inside the project-completed/ directory of the repository. This is the recommended learning path because it allows you to focus on understanding AI concepts and software engineering techniques without first having to build every lesson from scratch.

If you enjoy additional hands-on practice, you will also find a matching project-todo/ directory. These files contain scaffolded implementations with TODO sections that you can complete yourself. They are entirely optional and are intended as a challenge after you have already understood the completed implementation.

Recommended Learning Workflow

  • Watch the lesson.

  • Run the completed implementation from project-completed/.

  • Experiment with the implementation.

  • Optionally recreate the lesson later using the files inside project-todo/.

The course supports both macOS and Windows. Linux users can follow the macOS instructions since the commands are identical.

1.2 Windows Setup (Using WSL2)

If you are using Windows 10 or Windows 11, this course strongly recommends developing inside Windows Subsystem for Linux 2 (WSL2). Although Python can be installed directly on Windows, WSL2 provides a Linux environment that is fully compatible with modern AI and software engineering tooling.

Why WSL2?

  • The course includes Bash scripts for setup and launching applications.

  • Most AI frameworks are primarily developed and tested on Linux.

  • Package installation is generally more reliable.

  • File paths and virtual environments behave consistently with the examples demonstrated throughout the course.

  • You gain experience using the same operating system used by many cloud servers and development environments.

Step 1 — Install Windows Subsystem for Linux

Open Windows PowerShell as an Administrator.

Execute the following command.

wsl --install

This command installs Windows Subsystem for Linux together with the default Ubuntu distribution.

When installation finishes, restart your computer if prompted.

After restarting, Ubuntu will launch automatically and ask you to create a Linux username and password. These credentials are used only inside your Linux environment.

Note

Your Linux username and password are separate from your Windows login credentials.

Step 2 — Verify WSL Version

Open PowerShell again and run:

wsl --list --verbose

You should see output similar to:

NAME      STATE     VERSION

Ubuntu    Running   2

The important value is the VERSION column, which should be 2.

If your installation reports version 1, upgrade it using:

wsl --set-version Ubuntu 2

Step 3 — Open Ubuntu

You can launch Ubuntu in several ways.

Method            Description
----------------  -------------------------------------------------
Start Menu        Open Ubuntu directly from the Windows Start Menu.
PowerShell        Run wsl.
Command Prompt    Run wsl.
Windows Terminal  Select the Ubuntu profile.

From this point onward, every command shown in this course should be executed inside the Ubuntu terminal unless otherwise stated.

Step 4 — Update Ubuntu

Before installing development tools, update the operating system.

sudo apt update && sudo apt upgrade -y

This may take several minutes depending on your internet connection.

Step 5 — Verify Python

python3 --version

You should have Python 3.11 or newer.

If Python is missing or your version is older, install it using:

sudo apt install python3 python3-pip -y

Some Ubuntu versions may also require:

sudo apt install python3.11 -y

Verify once more after installation.

python3 --version

Step 6 — Install Development Tools

Several Python packages compile native extensions during installation. These require the standard Linux build tools.

sudo apt install build-essential curl git -y

This installs:

  • GCC

  • G++

  • Make

  • curl

  • Git

Step 7 — Verify Git

git --version

You should see Git version 2.x or newer.

Important

After completing this section, you can treat your Ubuntu terminal almost exactly like a Linux or macOS terminal. From this point onward, nearly every command shown throughout the course is identical regardless of whether you are using macOS or Windows with WSL2.

Expected Outcome

Requirement         Status
-----------------  ---------
WSL2 installed      ✓
Ubuntu installed    ✓
Python 3.11+        ✓
Git installed       ✓
Build tools        ✓

What Does the Setup Script Do?

The setup script automates all of the repetitive configuration steps required before developing AI applications.

Step                    Description
---------------------  ---------------------------------------------------

Why Use a Virtual Environment?

A virtual environment is an isolated Python installation that belongs only to this project. Instead of installing packages globally on your computer, each project maintains its own independent set of libraries.

Depending on your internet connection, the setup process may take several minutes because numerous AI libraries—including Streamlit, LangChain, OpenAI, ChromaDB and other dependencies—need to be downloaded and installed.

Please Be Patient

The first installation is always the longest. After the dependencies have been installed successfully, future lessons launch almost immediately because the packages are already available on your machine.

2.5 Configuring Environment Variables

Many lessons communicate with Large Language Models using cloud APIs. These services require authentication using API keys.

Rather than placing sensitive information directly inside source code, modern applications store credentials as environment variables. This improves security and makes it easy to switch between different providers.

Temporary Environment Variables

If you simply want to experiment, you can define API keys for the current terminal session.

export OPENROUTER_API_KEY="your-api-key"

export OPENAI_API_KEY="your-openai-key"

export ANTHROPIC_API_KEY="your-anthropic-key"

export COHERE_API_KEY="your-cohere-key"

export OLLAMA_URL="http://localhost:11434/completions"

These values remain available until the terminal window is closed.

You can verify an environment variable using:

echo $OPENROUTER_API_KEY

Persistent Configuration Using a .env File

For day-to-day development, storing configuration in a .env file is considerably more convenient.

Create a file named .env in the root of the repository.

OPENROUTER_API_KEY=your-api-key

OPENAI_API_KEY=your-openai-key

ANTHROPIC_API_KEY=your-anthropic-key

COHERE_API_KEY=your-cohere-key

OLLAMA_URL=http://localhost:11434/completions

Inside Visual Studio Code, search for the setting named Python: Env File and point it to the project's .env file. New terminals will automatically load these values.

Security Reminder

Your API keys are private credentials. Never publish them online, never include them in screenshots, and never commit your .env file to GitHub. The repository already includes a .gitignore file that prevents accidental commits.

How the Course Uses These Variables

The shared configuration utilities automatically read these environment variables whenever a lesson starts.

Variable              Purpose
--------------------  ---------------------------------------------
OPENROUTER_API_KEY     Recommended provider for most lessons.
OPENAI_API_KEY         OpenAI models.
ANTHROPIC_API_KEY      Claude models.
COHERE_API_KEY         Embedding generation.
OLLAMA_URL             Local LLM endpoint.

Individual lessons will indicate which provider they require. In most cases, OpenRouter is the recommended default because it provides access to multiple models through a single API.

3.1 OpenRouter Setup (Recommended)

OpenRouter acts as a unified gateway to many of today's most popular language models.

Instead of creating accounts with multiple AI providers, OpenRouter allows your applications to access numerous models using a single API.

Why OpenRouter?

  • Simple registration process.

  • No credit card required for the free tier.

  • Access to multiple model providers.

  • Excellent for learning and experimentation.

  • One API interface regardless of which model you choose.

Step 1 — Create an Account

Visit the OpenRouter website and create a free account.

You may register using your email address, GitHub account or Google account.

Step 2 — Generate an API Key

After signing in, navigate to the API Keys page and generate a new key.

Your key will resemble:

sk-or-v1-xxxxxxxxxxxxxxxxxxxxxxxx

Important

Treat your API key like a password. Anyone possessing your key can make requests on your behalf.

Step 3 — Add Some Credits (Recommended)

This is optional but adding even $5 or $10 can unlock some generous limits.

Step 4 — Configure Your Environment

If you are using a .env file, simply add:

OPENROUTER_API_KEY=sk-or-v1-your-api-key

Alternatively, configure it temporarily in your terminal.

export OPENROUTER_API_KEY="sk-or-v1-your-api-key"

Verify the variable has been configured successfully.

echo $OPENROUTER_API_KEY

How the Course Uses OpenRouter

The course configuration automatically reads your OpenRouter API key whenever an application starts.

For most lessons, no additional configuration is required. Once your API key has been added, the completed projects demonstrated throughout the course will communicate with OpenRouter automatically.

Behind the Scenes

The shared configuration utilities inside the repository load your environment variables and configure the correct provider automatically. This keeps lesson code clean and allows you to switch providers without modifying application logic.

4.10 Troubleshooting Guide

Problem                     Likely Cause                                Suggested Solution
-------------------------  ------------------------------------------  ------------------------------------------------------
Python command not found    Python is not installed or not on PATH      Revisit Section 1 and verify your Python installation.
Module not found            Virtual environment is not activated       Activate .venv before running the lesson.
API authentication failed   API key missing or incorrect               Verify your environment variables or .env file.
Streamlit command not found Dependencies were not installed successfully Run ./setup.sh again.
Browser does not open       Automatic launch failed                    Open http://localhost:8501 manually.
Package installation errors Internet connection or missing system dependencies Verify your operating system setup and rerun the installation.

Remember

Nearly every setup issue can be traced back to one of four causes:

  1. The virtual environment is not activated.

  2. An API key has not been configured.

  3. The required Python packages were not installed.

  4. The operating system setup was not completed correctly.
