## SUBSECTION 1A: MACOS SETUP

**Target Users:** macOS (Intel and Apple Silicon)

**Opening Context:** 
Most macOS users already have the required tools. This section is a quick verification
step with minimal setup needed.

**Steps to include:**

1. **Verify Terminal Access**
   - macOS ships with Terminal.app pre-installed
   - Alternative: Install iTerm2 (https://iterm2.com/) for enhanced terminal features
   - Both work equally well; choice is personal preference

2. **Verify Python 3 Installation**
   - Command to verify: `python3 --version`
   - Expected output: Python 3.11 or higher (course requires Python >= 3.11 per pyproject.toml)
   - If Python 3 is not installed:
     - Option A (Recommended): Install Homebrew first (https://brew.sh/), then run `brew install python3`
     - Option B: Download from python.org (https://www.python.org/downloads/)
     - Verify installation after: `python3 --version`

3. **Verify Git Installation**
   - Command: `git --version`
   - Expected output: git version 2.x or higher
   - If not installed: `brew install git`

4. **Verify pip (Python Package Manager)**
   - Command: `pip3 --version`
   - Expected output: pip version 20.0 or higher
   - If not available: `python3 -m ensurepip --upgrade`

**Outcome:** You have Python 3.11+, git, and pip3. Ready to proceed to Section 2.

## SUBSECTION 1B: WINDOWS SETUP

**Target Users:** Windows 10/11

**Opening Context:**
Windows requires Windows Subsystem for Linux (WSL) to run this course environment
properly. WSL provides a native Linux kernel inside Windows, ensuring compatibility
with all course scripts and dependencies that assume POSIX/Linux conventions.

**Why WSL and not native Windows Python?**
- Course uses bash scripts (setup.sh, run_streamlit.sh, run_cli_agent.sh)
- Virtual environment paths and symlinks work correctly in WSL
- Most AI/ML tooling community develops primarily for Linux/macOS
- WSL 2 has near-native performance on modern Windows systems

**Steps to include:**

1. **Enable WSL 2 (Windows Subsystem for Linux 2)**
   - Open Windows PowerShell as Administrator (right-click, "Run as administrator")
   - Run: `wsl --install` (this installs WSL 2 and default Ubuntu distribution)
   - Restart your computer when prompted
   - On restart, a terminal will launch for first Ubuntu setup; create a Unix username and password
   - Detailed guide: https://learn.microsoft.com/en-us/windows/wsl/install

2. **Verify WSL 2 is Running**
   - In Windows PowerShell: `wsl --list --verbose`
   - You should see your Ubuntu distribution with VERSION = 2
   - If it shows VERSION = 1, upgrade with: `wsl --set-version Ubuntu 2`

3. **Open Ubuntu Terminal**
   - Method A: Start Menu → "Ubuntu" → Click to open
   - Method B: Windows PowerShell or Command Prompt → run `wsl`
   - You are now in a Linux bash shell

4. **Update Package Manager Inside Ubuntu**
   - Run: `sudo apt update && sudo apt upgrade -y`
   - This ensures your Linux system has the latest packages

5. **Verify Python 3 Inside Ubuntu**
   - Command: `python3 --version`
   - Expected: Python 3.11 or higher
   - If not installed or version is too old:
     - Run: `sudo apt install python3.11 -y` or `sudo apt install python3 python3-pip -y`
     - Verify again: `python3 --version`

6. **Install Required Build Tools**
   - Some Python packages compile native extensions; you need build tools
   - Run: `sudo apt install build-essential curl git -y`
   - This installs gcc, g++, make, curl, and git

7. **Verify Git Installation**
   - Command: `git --version`
   - Should show git 2.x or higher; if not in previous step, it's now installed

**Outcome:** You have WSL 2 running Ubuntu with Python 3.11+, git, and build tools.
All subsequent commands in this lesson are run inside the Ubuntu terminal (WSL 2).
From this point forward, Windows and macOS instructions converge.

**Opening Context:**
The course repository contains both completed lessons (reference implementations)
and scaffolded lessons (project-todo/) where you implement TODOs. You'll clone the
repository and set up a virtual environment.

**Steps to include:**

1. **Clone the Repository**
   - Open a terminal (macOS: Terminal or iTerm2; Windows: WSL Ubuntu terminal)
   - Choose a workspace directory (e.g., ~/Code or ~/Documents)
   - Run: `cd ~/Code` (or your chosen directory)
   - Clone the repository:

   - In VS Code's integrated terminal (Ctrl+` or View → Terminal):

## SUBSECTION 2C: ENVIRONMENT VARIABLES SETUP

**Opening Context:**
The course uses API keys for LLM providers (OpenAI, Anthropic, OpenRouter, Cohere).
Rather than hardcoding these in code, they're managed via environment variables.
You can set these in your terminal session or in VS Code settings.

**Steps to include:**

1. **Temporary Setup (Per Terminal Session)**
   - Useful for testing; settings are lost when terminal closes
   - In your activated terminal (.venv), run:
     ```bash
     export OPENROUTER_API_KEY='your-actual-key-here'
     export OPENAI_API_KEY='your-key-if-using-openai'
     export ANTHROPIC_API_KEY='your-key-if-using-anthropic'
     export COHERE_API_KEY='your-key-if-using-cohere'
     export OLLAMA_URL='http://localhost:11434/completions'  # if using local Ollama
     ```
   - Verify: `echo $OPENROUTER_API_KEY` (should print your key)

2. **Persistent Setup (Optional: VS Code Settings)**
   - Allows keys to persist across terminal sessions within VS Code
   - In VS Code: File → Preferences → Settings (Ctrl+,)
   - Search for "Python: Env File"
   - Set the value to: `.env`
   - Create a `.env` file in the repository root:
     ```bash
     # Example .env file
     OPENROUTER_API_KEY=your-key-here
     OPENAI_API_KEY=your-key-if-applicable
     ANTHROPIC_API_KEY=your-key-if-applicable
     COHERE_API_KEY=your-key-if-applicable
     OLLAMA_URL=http://localhost:11434/completions
     ```
   - Save the file
   - VS Code will load these variables automatically when you open a new terminal
   - **Important:** Add `.env` to `.gitignore` (already present in the repo)
     to prevent accidentally committing API keys to GitHub

3. **Provider Configuration in Code**
   - The course uses `shared/utils/settings.py` to load these environment variables
   - This module is imported by all lessons and handles provider selection
   - Supported providers:
     - OpenRouter (URL-based, free-friendly, recommended): `OPENROUTER_API_KEY`
     - OpenAI (requires paid account): `OPENAI_API_KEY`
     - Anthropic (requires paid account): `ANTHROPIC_API_KEY`
     - Cohere (for embeddings, free tier): `COHERE_API_KEY`
     - Ollama (local, free): `OLLAMA_URL`
   - Each lesson will tell you which provider it uses and which environment variable to set
